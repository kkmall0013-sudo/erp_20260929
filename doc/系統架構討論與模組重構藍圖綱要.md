## 📌 第一章：介面佈局與經典三子視窗配置核心哲學

### 1.1 「右側滑動、左欄絕對不動」之正統 ERP 交互鐵律
- **問題回顧**：先前版本嘗試將視窗切成對等雙大視窗（Split Pane），導致左邊也是大表單、右邊也是大表單，版面嚴重擁擠、滾動混亂。
- **正統 ERP 標準視窗配置**：
  1. **最左側導航欄 (Sidebar, ~220px)**：永遠鎖定固定（Sticky），不隨右側內容滾動。提供一鍵收合為 56px 微型圖示模式。
  2. **左側固定子視窗 (Sub-window Master List, ~280~320px)**：
     - 欄位精巧固定、佔地不大，專門負責「單據待辦清單 / 工區案場樹 / 快速搜尋過濾」。
     - 具備**獨立內部滾動條**，滾動左側清單不影響右側。
     - 支援一鍵向左收折（Dock Strip），需要全螢幕超寬畫布時隨時收合。
  3. **右側超寬主工作畫布 (Detail Canvas, 佔據螢幕 75%~85%)**：
     - **固定頂部工具列 (Frozen Action Bar)**：單號、版次（REV-A）、狀態標籤，以及【新增】、【儲存】、【呈核審批】、【列印報表】按鈕永遠凍結在頂部。
     - **獨立內容滾動區**：放極致寬敞的工程工料明細表（10~15 欄位）、多期估驗試算。**滑鼠在右側滾動時，左側 Sidebar 與子視窗 100% 紋風不動**。
     - **表格表頭固定 (Sticky Table Header)**：滾動到第 100 筆工料，欄位名稱依然停在表格頂端。

## 📌 第二章：三層式權限架構與 2D 矩陣式多群組 (PBAC)

### 2.1 三層身分階層 (Three-Tier Identity)
1. **Tier 1 - 唯一最高管理者 (Superadmin)**：
   - 系統僅限 1 位，享有憲法級金身保護。
   - 審批額度無上限（Unlimited），掌握底層系統參數變更與資料庫完整備份還原。
   - 一般 Admin 與 User 無法停用、修改角色或刪除 Superadmin；職位交接必須由現任 Superadmin 親自執行交接程序。
2. **Tier 2 - 系統管理員 (Admin, 若干位)**：
   - 負責日常工區所長、資訊主管之帳號分發與群組授權維護，受憲法防呆邊界約束，無法刪除其他 Admin 或篡改 Superadmin。
3. **Tier 3 - 一般業務同仁 (User 群組)**：
   - 依所屬業務群組獲得最小必要權限（Principle of Least Privilege）。

### 2.2 2D 矩陣式多群組聯集授權 (PBAC Matrix Grid)
- **多群組同時指派**：同仁可同時隸屬於多個業務群組（例如同時擁有「工務組」與「專案業務組」）。
- **動態權限聯集 (Union Evaluation)**：
  - 各模組的讀取 (Read)、編輯 (Write)、核准 (Approve)、匯出 (Export) 採聯集運算（任一群組允許即為允許）。
  - **單筆審核上限取最高者 (Max Approval Limit)**：同仁所獲得之單筆審批額度自動取所屬群組中之最大值。

## 📌 第四章：底層資料庫與憲法防弊原則

1. **SQLite 本地便利資料庫與備份還原演進**：
   - 零設定免連線字串，隨選運行。
   - **全庫鏡像模式 (Ghost) 與雙通道介面統一**：
     - 頂部導航列 (TopSubWindow) 與基本資料 (BasicSettingsHubWorkspace) 雙通道操作與命名 100% 統一。
     - **全庫檔案一鍵上傳直接還原 (Direct File Restore)**：直接選取或拖曳上傳 `.sqlite`、`.db` 實體庫或 `.sql` 指令檔，自動辨識格式與體積，提示安全預警與下載備份防呆，1 秒內以 WebAssembly 掛載覆寫，無需重啟伺服器。
     - **一鍵二進位下載 (.sqlite)** 與 **全庫 SQL 匯出 (.sql)**：隨身碟離線攜帶與標準 SQL 移植備份。
   - **模組化選擇性備份 (Modular Backup/Restore)**：支援多人分工開發與測試時，僅勾選特定模組獨立匯出與匯入，支援覆蓋 (Replace) 與略過 (Skip)。支援歷史全部、指定年度、起訖區間（RANGE）之精準時段過濾。
   - **年度唯讀封存快照 (Annual Archival Snapshots)**：經 2010～2026 年（17 年歷史跨度）實機測試驗證，歷年封存資料庫獨立唯讀隔離，介面實體化完整清冊可查閱與下載。
   - **單據跳號防回溯、產號防碰撞自癒與備份還原一致性 (Post-Restore Re-seed)**：嚴格禁止流水號計數器回溯修改；產號引擎 (`getNextDocumentNumber`) 自動防撞躍升杜絕重號；全庫備份還原後系統自動執行 `reseedDocumentSequences()` 自動重置對齊指針，保證還原後開單 100% 不撞號。
   - **開發注意事項 (Developer Discipline)**：日常單據開立一律調用 `getNextDocumentNumber(moduleKey, docDate)`，禁止寫死序號；前綴變更嚴禁跨模組重疊 (`validateDocumentPrefixConflict`)。
2. **全域零負數鐵律**：
   - 折讓、代購扣款、減項均以正數保存，介面強制以粉紅扣款（Pink Deduction UI）醒目警示。
3. **過帳實體快照 (Frozen Snapshot)**：
   - 任何合約、估驗、採購單過帳後，其交易夥伴、專案名稱、稅率與金額永久鎖定，杜絕歷史竄改。
4. **沙盒模擬與 iframe 友善 (No window.confirm)**：
   - 全面禁用會被 iframe 靜默封鎖的原生 `window.confirm` / `alert`，一律使用專屬 React 防呆確認 Modal。

## 📌 第五章：進貨管理與會計對帳水池專責切分與雙重確認權限設計

### 5.1 進貨模組專責範疇（現場進貨簽收與料件單價管理）
1. **直入案場成本 (A 模式)**：材料送達現場後，進貨即直接歸戶該專案成本，不入中心庫存倉庫，不需額外做領料調撥。
2. **進貨單核心欄位**：
   - 進貨日期、合作廠商 (VENDOR)、歸屬案場 (PROJECT)。
   - 廠商送貨單號 / 現場簽收單號（實體紙本簽收單編號，方便月底對帳勾稽）。
   - 簽收憑證影像／附件（支援手機現場拍照或上傳簽收單影本）。
   - 物料明細表：材料品名、規格、單位、進貨數量、約定單價、行小計金額。
   - 狀態生命週期：`草稿 (DRAFT)` ➔ `已簽收入庫 / 待對帳 (PENDING_BILLING)` ➔ `已對帳請款 (BILLED)` ➔ `已作廢 (VOIDED)`。
3. **嚴格不碰之邊界 (Strict Non-Scope)**：
   - ❌ **不打發票號碼**：發票何時開、開幾張、免用發票或跨期延後，完全由會計端對帳時決定。
   - ❌ **不做折讓扣款**：現金領款折讓、零頭扣抵皆屬財務對帳範疇，不污染進貨實體數量與單價。
   - ❌ **不排定付款日期與放款**：不在此決定支票票期或匯款日期。

### 5.2 會計對帳「廠商往來大水池 (Vendor Ledger Pool)」機制
1. **進貨沉澱於水池**：現場進貨審核後，自動以 `PENDING_BILLING` 狀態沉澱於該廠商的未對帳大水池中。
2. **月底對帳單勾稽作業**：
   - 會計收到廠商請款單／對帳單時，拉出該廠商水池中所有待對帳進貨單。
   - 逐筆核對實體簽收單，無疑問者勾選請款；若當期無發票或有疑義，單據放著不勾選，自動留在水池中順延至下期對帳。
   - 會計勾選確認後，輸入發票號碼（或註記免用發票/跨期延後補票）、計算營業稅 (5%)、登打折讓扣減（如領現金折讓、零頭扣款），產出本期應付淨額。

### 5.3 廠商欠款水位與預計付款日提醒
1. **欠款水位總表 (Vendor Aging & Payable Dashboard)**：
   - 戰情儀表板即時呈現「全公司目前欠哪幾家廠商多少水（未結進貨款總額）」。
   - 顯示各筆款項之「預計付款日」，並以紅黃綠燈進行到期預警（如「7 天內到期」、「已逾期」），方便出納與老闆精準調度資金。
2. **放款與票據沖銷**：
   - 放款時開立現金、支票或銀行電匯，沖銷應付帳款，完成進貨到付款完整閉環。

### 5.4 PBAC 雙重確認權限設計 (Separation of Duties)
1. **三權在底層完全獨立**：
   - **打單權限 (CAN_INPUT_INBOUND)**：僅限新增、修改草稿、送出進貨簽收單。
   - **對帳權限 (CAN_RECONCILE_AP)**：僅限將待對帳單據勾稽、補發票、填折讓、產出應付對帳單。
   - **付款權限 (CAN_DISBURSE_AP)**：僅限審核付款排程、開立支票、放款沖銷。
2. **現行二人兼任配置 vs 未來擴展**：
   - 現行二人制：人員 A 具備「打單 + 對帳」，人員 B 具備「對帳 + 付款」，對帳環節形成雙重確認交叉防弊。
   - 未來擴編制：系統可隨時在後台切換為 A (專職打單)、B (專職對帳)、C (專職放款) 三人完全分立，架構無需改寫。

### 5.5 模組對接錨點 (Data Hooks)
1. 每筆進貨單產生唯一系統單號（`INB-YYYYMM-XXXX`）。
2. 明細行具備唯一鍵值與專案歸屬。
3. 進貨單預留 `reconciliationId` 外鍵欄位（初始為 `NULL`，狀態為 `PENDING_BILLING`；會計對帳過帳時自動寫入對帳單號並轉為 `BILLED`）。

## 📌 第六章：全新左側功能選單順序排列哲學、業務流程雙保險與系統中樞整併

### 6.1 左側功能選單「增減與重整」排序哲學（9+1 結構）
1. **常用業務順序排列原則**：
   - 傳統 ERP 常將基本資料、程式設定等低頻維護項目與日常業務混在一起，甚至排在頂端，造成操作干擾。
   - 本系統依據營造工程真實作業動線，將最常操作的業務模組依生命週期由上至下依序排列：
     1. **營運儀表 (DASHBOARD)**：置頂整體現況與 1~7 階業務生命週期地圖。
     2. **案場工程 (PROJECTS)**：合約工區主檔，工程專案開工之始。
     3. **廠商工班 (PARTNERS)**：業主 (CRM) 與協力廠商工班 (SRM) 庫。
     4. **報價預算 (QUOTATIONS)**：工程估價、版次鎖定與利潤試算。
     5. **進貨管理 (INBOUND)**：現場材料驗收簽收，A 模式直接認列案場成本。
     6. **估驗請款 (VALUATIONS)**：下包累計估驗、保留款扣抵與計價。
     7. **財務收支 (FINANCE)**：應收應付帳款 (AP/AR) 與開票兌現管理。
     8. **保險箱   (VAULT)**：工程圖說、合約附件與無紙化金庫。
     9. **戰情指揮 (COMMAND_CENTER)**：全集團現金水位、專案毛利大水池 (BI)。
     --- 【細緻分隔線】 ---
     10. **系統中樞 (SETTINGS)**：整合基本資料、帳號管理、程式設定、小程式庫、藍圖總綱於單一頁面，置於最底層。

### 6.2 業務流程去裝飾化：全面回歸實戰作業與教育訓練模組化規劃
1. **全面拔除裝飾性流程圖之決策背景**：
   - 經實機操作檢視，舊有靜態流程圖存在 5 大致命硬傷：
     1. 標題無法隨公司與案場動態連動。
     2. 檢視動線（採購/銷售/財務切換）僅為靜態色塊過濾，無實質業務價值。
     3. 互動作業節點為靜態擺設，缺乏真實表單穿透邏輯。
     4. 底層權限矩陣與參數設定重複且無實效。
     5. 權限顛倒：僅 Admin 可看（管理員已熟悉系統不需看，一般同仁需要 SOP 卻看不到）。
2. **斷捨離處置（回歸純粹實戰）**：
   - 頂部導航列全面卸載「業務流程」按鈕與彈窗，絕不堆疊無效按鈕。
   - 營運儀表板內部移除「展開完整流程圖」接口，僅保留極致俐落的 1~7 常用業務推進軸 (`BusinessLifecycleMapCard`)，點擊直接穿透切換至各模組。
3. **教育訓練獨立模組化規劃**：
   - 未來若有新進同仁培訓需求，不將教材混雜於日常操作畫面中，而是另闢獨立之「教育訓練模組 (Training Module)」，依登入角色（工務/會計/業務）提供專屬的真實 SOP 指南與表單教學。

### 6.3 五合一底層系統管理中樞 (`SystemHubWorkspace`)
1. **五大功能整併為單一頁面**：
   - 將「營運基本資料」、「帳號與權限管理」、「軟體程式設定」、「常用小程式庫」、「藍圖總綱與規約」整併於 `SystemHubWorkspace`，以頂部 Tab 標籤切換。
2. **三層身分與 RBAC 嚴格授權分流**：
   - **Tab 1: 營運基本資料 (BASIC)**：法人設定、法定稅制、合約慣例、單據跳號、資料庫備份 *(Admin / Superadmin)*。
   - **Tab 2: 帳號與權限 (USERS)**：使用者名冊、身分權限矩陣、審批額度、安全稽核 *(Superadmin 或特許 Admin)*。
   - **Tab 3: 軟體程式設定 (APP_SETTINGS)**：軟體抬頭品牌、版本號、全域公告廣播、Feature Flags *(Superadmin 專屬)*。
   - **Tab 4: 常用小程式庫 (MINI_APPS)**：台灣 3+3 郵遞區號選取器、全國 414 家金融機構/農漁會速查 *(共用工具庫)*。
   - **Tab 5: 藍圖總綱與規約 (ROADMAP)**：憲法規約手冊、系統架構討論綱要 *(Superadmin 專屬)*。
   - 一般同仁 (USER) 無系統設定權限者，左側底層按鈕完全不予顯示，徹底杜絕越權。

### 6.4 進貨管理優先與採購發包之架構邊界
1. **目前聚焦進貨管理**：
   - 進貨管理 (INBOUND) 聚焦於材料工區簽收、拍照存證與直入案場成本（A 模式）。
   - 採購發包 (PROCUREMENT) 暫時自選單隱藏，未來若企業需擴充大宗物料詢價議價、發包比價單時，再以獨立模組無縫掛載，互不干擾。
