# 🏛️ 客製化營造工程 ERP 系統技術文件總覽 (Documentation Hub)

本目錄彙整本 ERP 系統之系統架構、開發內控規範、業務模組定義與全庫資料庫規格，為全體開發人員與維運主管之單一真實來源法典 (SSoT)。

> **🧩 最高程式寫作憲法：功能導向「小程式化」分拆與組裝（拒絕單體龐然大物）**
> 1. **能拆就拆，嚴禁寫出千行龐然大物**：任何業務能力（如對客請款表、支票統計雷達、暫收池認領、401 申報簿、資料表單彈窗、資料計算引擎）一律依「**功能導向**」獨立拆寫為輕量小程式／子模組（建議每檔 200～600 行，上限 800 行），最後再由輕量容器工作台或組裝層串聯起來。
> 2. **同時保障人力維運與 AI 上下文長度**：小程式分工明確，修改單一業務規則不會誤傷其他模組；同時徹底避免檔案動輒數千行導致 AI 讀取與開發時上下文過長、遺漏狀態或改錯程式。
> 3. **既有巨型檔案漸進瘦身實績**：已完成 `M02`～`M09` 八大模組拆解（含 `src/db/sqlite.ts` 由 14,476 行 ➔ 84 行拆為 29 支無循環模組、`src/types/erp.ts` 由 1,158 行 ➔ 8 行、以及各主工作台大幅瘦身），剩餘逾 800 行檔案列管為 Freeze & Shrink 名單漸進收斂（詳見《開發注意事項.MD》第十六章）。

   - 遵循「回歸純粹實戰，不做花架子」原則，將系統資源 100% 聚焦於日常工程錄入與審核。

## 🛡️ 資料庫備份還原與編碼防撞核心規範摘要

1. **單據編碼規則與前綴防撞 (Prefix Conflict Prevention)**：
   - 業務模組前綴必須全域唯一（例如 `AP` 屬應付帳款，嚴禁 `AR` 或其他模組重疊使用）。
   - 變更前綴時（例如 `AP` ➔ `PP`），過往單據作為法定會計憑證永久保留不改號，新單據自動自新前綴第一號接續開單。
2. **雙角色視角分流 (Role-Based Perspectives)**：
   - **Admin 業務主管**：簡潔的編碼規範表、當期配發預覽、下月預約號碼，無多餘底層技術雜訊。
   - **Superadmin 程式設計師**：底層指針即時監控、歷史舊單匯入防撞審計、全庫還原一致性指針自動校準。
3. **資料庫全庫備份與直接還原一致性 (Direct Database Restore)**：
   - 頂部導航列 (TopSubWindow) 與基本資料 (BasicSettingsHubWorkspace) 雙入口 100% 統一。
   - 支援 `.sqlite` / `.db` 二進位實體檔案與 `.sql` 純文字指令檔一鍵拖曳／選取上傳。
   - 系統自動解析檔案類型與大小，提示安全覆蓋預警，提供「還原前先下載當前庫備份防呆 (建議)」按鈕。
   - 1 秒內以 WebAssembly 掛載覆寫，完成後**自動調用 `reseedDocumentSequences()` 全自動校準 12 大模組單據流水號指針**，防止撞號與主鍵衝突。

## 🏗️ 案場建造物二階字典、預算協力廠商發包與防裁切懸浮選單

1. **建造物類型自訂兩階層字典 (`BUILDING_CATEGORY_TREE`)**：
   - 解決硬編碼類型無法適應不同營造行業與工種之限制。
   - 採「大項 ➔ 小項」結構，表單嚴格約束僅能選取第二階小項，大項僅供分類群組展示。
   - 提供專屬 `BuildingCategoryManagerModal` 支援自主維護大類與細項。
2. **預計協力廠商發包預算主表 (`project_budget_partners`)**：
   - 支援案場新增時預估各工料協力廠商與預估發包金額。
   - 建立 `idx_budget_partners_project` 複合索引提升彙整效能。
3. **二階協力廠商公司名稱字典 (`SUBCONTRACTOR_CATEGORY_TREE`)**：
   - 核心原則：**清單只需公司名稱，不用冗長細部資料**（避免干擾）。
   - 第一階工料分類（鋼材、混凝土、拆圖、屋頂浪板等），第二階為該分類下之公司名稱清單。
4. **懸浮式選單防裁切架構 (Floating Portal Architecture)**：
   - 徹底杜絕響應式表格 `overflow-x-auto` 或彈窗 `overflow-y-auto` 裁切遮蔽下拉選單的問題。
   - 使用 `ReactDOM.createPortal(..., document.body)` 搭配 `fixed` 絕對座標定位與 `z-[99999]`。
5. **進貨與計價唯讀對帳與待請款差額檢警機制**：
   - 只由進貨端與計價端調取資料彙整，嚴禁修改。
   - 自動核算 $\text{待請款差額} = \text{累計已進貨} - \text{累計已請款}$，差額 > 0 時標註顯眼「待請款」警示，杜絕協力廠商忘記請款之漏洞。
   - 點擊廠商時提供獨立隔離穿透對帳視窗 (`ProjectVendorInboundModal`)，嚴密過濾單一案場單一廠商之進貨單據明細。

## 📦 進貨簽收、極速打單工作台與廠內自用成本收斂 (Inbound Workspace & PRJ-INTERNAL)

1. **防幽靈案場憲法 (Anti-Ghost-Project Constitution)**：
   - 嚴格禁止進貨打單端呼叫 `quickCreateProject()` 建立虛假專案。
   - 工程案場打入未確認簡稱時，引導至正規專案主檔建檔，確保專案契約與預算資料完整。
2. **單一內部成本中心專案 (`PRJ-INTERNAL`)**：
   - 廠內公務車保養維修（如 `廠內貨車 [358-AB]`）、廠務修繕（如 `廠房修繕 (屋頂翻修/地坪/水電)`）、公共常備備料一律外鍵收斂至 `PRJ-INTERNAL`。
   - 具體用途標的以標準全銜記錄於單據快照 `projectNameSnapshot`，兼顧關係代數完整性與現場辨識便利性。
3. **輸入層即時強制正規化 (onBlur Normalization)**：
   - 現場或 Excel 匯入輸入簡稱（如 `358`、`776`、`中鋼`、`備料`）時，儲存格失焦即時強制轉換為標準全銜（如 `廠內貨車 [358-AB]`、`中國鋼鐵股份有限公司`、`廠內公共儲備庫存 (常備用料)`）。
4. **多草稿抽屜生命週期與過帳工作台清空**：
   - 送貨單號預設空白，由現場如實抄錄。
   - 支援將鍵檔中單據暫存為獨立草稿（`DRAFT`），並可隨時新增草稿、切換草稿抽屜繼續鍵檔。
   - 正式過帳入水池後，工作台自動重置清空，杜絕上一筆單據資料殘留干擾。
5. **資產庫職能邊界隔離**：
   - 車輛資產產權、購置與折舊屬會計資產管理範疇；現場進貨端移除資產庫維護按鈕，回歸純粹點收歸屬標籤選取。

## 💰 財務會計與出納分權架構、三階段水池與票據資金雷達 (Finance & Cashier Architecture)

1. **會計管帳 vs 出納管錢，1 人兼任 ⇄ 2 人分權無縫切換**：
   - **專職會計 (`GRP-PURE-ACC` / 測試帳號 `acc_a`)**：僅開啟 `FINANCE_AP`、`FINANCE_AR`、`INBOUND_RECEIPTS` 唯讀；對帳 Modal 專注核對進貨金額、折讓、動態 `TAX_RATE` 稅額、發票號碼與買受法人，不選銀行或支票期日。
   - **專職出納 (`GRP-CASHIER` / 測試帳號 `cashier_b`)**：僅開啟 `BANK_CHECKS`；依會計核准立帳單據選擇付款方式、合規公司銀行專戶、可調支票號碼與 3 個月排程到期日。
   - **一人兼任 (`GRP-ACC` / 測試帳號 `fin_c`)**：測試密碼統一為 `888888`；對帳視窗額外解鎖「⚡ 核准立帳 ＋ 立即出納付款」一鍵連貫放款，未來擴編為兩人時僅改帳號群組免改程式。
2. **AP 三階段生命週期與雙向退回防重閉環**：
   - TAB 1 明確分為 **「1. 會計待辦處理大水池（出納退回重算 + 未送草稿 + 待對帳新進貨）」➔「2. 已送出納審核／待放款中（會計催款追蹤）」➔「3. 已完全完工備查清冊（預設 `PAID`）」**。
   - 出納可將異常對帳單一鍵退回會計重算 (`APPROVED -> RETURNED`)；`DRAFT`/`RETURNED`/`APPROVED`/`PAID` 全程鎖定進貨單 (`BILLED`) 並搭配重複請款偵測與一鍵去重清理，杜絕重複請款。
3. **動態稅制、老闆私帳政策與支票兌現日雷達**：
   - 營業稅即時讀取 `TAX_RATE`，免稅強制歸零並清除殘留手調稅額；出納卡片與付款視窗完整呈現未稅／稅額／含稅三欄金額。
   - 受 `BOSS_ACCOUNT_INVOICE_POLICY` (`STRICT_INVOICE_MATCH` / `ALLOW_BOSS_ADVANCE`) 與法人嚴格専戶過濾保護；支票排程依 **專戶 ➔ 公司 ➔ 全域 `PAYMENT_SCHEDULE_DAYS`** 三層繼承展開三個月快選。
   - 支票雷達支援依預計兌現日搜尋、區間快選、四向排序與「篩選區間每日應付支票現金統計」；退票支援 `REPAY`（重付）與 `REBILL`（整筆重請）雙軌回滾。
4. **AR 收入閉環、401 申報簿與功能小程式化拆分**：
   - 完成業主應收立帳 (`accounts_receivable`)、多元收款 (`fin_ar_collections`)、已知案場貸款／溢收直掛 (`fin_project_advances`) 與未知暫收池分批認領 (`fin_suspense_receipts`)、雙月 401 進銷項與預計請款模擬 (`fin_planned_invoices`)。
   - **對客請款三模式 (`APP_CUSTOMER_BILLING_MODE`) 與小程式拆分**：由 BOSS／Superadmin 決定採 `FINANCE_ONLY`（模式 A 預設）、`PROJECT_FIRST_HANDOFF`（模式 B 工務送審轉會計）或 `PROJECT_AND_FINANCE`（模式 C 雙軌），並已將 `CustomerStatementMiniApp`、`CheckRadarMiniApp`、`SuspensePoolMiniApp`、`Tax401WorkbookPanel` 抽離為獨立小程式，嚴守單檔體積與內外帳實體隔離規範。
