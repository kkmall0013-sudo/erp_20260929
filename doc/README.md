## 🧭 全新左側選單結構與系統管理中樞 (9+1 藍圖)

依據業務常用順序與營造生命週期，選單採「常用在上方、設定在下方」之階層重整：

```text
┌─── 【業務常用主幹道（依營造工程生命週期動線）】
│ 1. 營運儀表 (DASHBOARD)      ── 總體營運狀況、KPI 指標 ＋ 置頂業務生命週期地圖 (1~7 節點)
│ 2. 案場工程 (PROJECTS)       ── 專案主檔、工區規劃、工程合約架構
│ 3. 廠商工班 (PARTNERS)       ── 業主名冊 (CRM) 與協力廠商工班 (SRM)
│ 4. 報價預算 (QUOTATIONS)     ── 估價單編製、成本版次鎖定與利潤分析
│ 5. 進貨管理 (INBOUND)        ── 現場材料設備驗收，A 模式直入案場成本
│ 6. 估驗請款 (VALUATIONS)     ── 下包計價估驗、累計估驗與保留款扣抵
│ 7. 財務收支 (FINANCE)        ── 應收應付帳款 (AP/AR) 與開票兌現管理
│ 8. 保險箱   (VAULT)          ── 圖說規範、合約附件與無紙化金庫
│ 9. 戰情指揮 (COMMAND_CENTER) ── 全域現金水位、專案毛利大水池 (BI)
├─── 【細緻分隔線】
└─── 【底層管理維護區】
 10. 系統中樞 (SETTINGS)       ── 僅 Admin / Superadmin 可見，內建 5 大 Tab 分頁
```

### ⚡ 業務生命週期快速穿透與流程圖去裝飾化原則 (Pure Operational Efficiency)
1. **全面拔除裝飾性流程圖**：
   - 移除頂部導航列「業務流程」按鈕與彈窗，並移除儀表板內「展開完整流程圖」接口。
   - 經架構審查確認：舊有流程圖標題無連動、動線與作業節點無實質操作功能，且存在「管理員不需要看、一般同仁看不到」之權限矛盾。
   - 遵循「回歸純粹實戰，不做花架子」原則，將系統資源 100% 聚焦於日常工程錄入與審核。
2. **營運儀表板置頂業務生命週期推進軸 (`BusinessLifecycleMapCard`)**：
   - 在儀表板最上方保留極致精鍊的 1~7 階業務生命週期推進軸（案場 ➔ 廠商 ➔ 報價 ➔ 進貨 ➔ 估驗 ➔ 財務 ➔ 戰情）。
   - 帶有實時案場數與單據計數徽章，點擊任一節點可直接穿透跳轉至該模組。
3. **教育訓練獨立模組化規劃**：
   - 未來若企業擴編需要新進人員培訓或各崗位操作指引，將規劃獨立的「教育訓練模組 (Training Module)」，依登入角色（工務/會計/業務）提供專屬的真實 SOP 指南，不在日常作業介面堆疊無效圖表。

### 🧩 系統設定中樞 (System Hub) 五合一 Tab 分頁架構
- **Tab 1: 營運基本資料 (BASIC)**：法人設定、法定稅制、合約慣例、單據跳號、資料庫備份 *(Admin / Superadmin)*
- **Tab 2: 帳號與權限 (USERS)**：使用者名冊、三層身分矩陣、PBAC 授權、審核限額 *(Superadmin 或特許 Admin)*
- **Tab 3: 軟體程式設定 (APP_SETTINGS)**：抬頭版本、主題主色調、全域公告、Feature Flags *(Superadmin 專屬)*
- **Tab 4: 常用小程式庫 (MINI_APPS)**：台灣 3+3 郵遞區號選取器、全國 414 家金融機構速查 *(共用工具)*
- **Tab 5: 藍圖總綱與規約 (ROADMAP)**：系統架構討論記錄、憲法規約與重構綱要 *(Superadmin 專屬)*

## 🛡️ 資料庫備份還原與編碼防撞核心規範摘要

1. **單據編碼規則與前綴防撞 (Prefix Conflict Prevention)**：
   - 業務模組前綴必須全域唯一（例如 `AP` 屬應付帳款，嚴禁 `AR` 或其他模組重疊使用）。
   - 變更前綴時（例如 `AP` ➔ `PP`），過往單據作為法定會計憑證永久保留不改號，新單據自動自新前綴第一號接續開單。
2. **雙角色視角分流 (Role-Based Perspectives)**：
   - **Admin 業務主管**：簡潔的編碼規範表、當期配發預覽、下月預約號碼，無多餘底層技術雜訊。
   - **Superadmin 程式設計師**：底層指針即時監控、歷史舊單匯入防撞審計、全庫還原一致性指針自動校準。
3. **資料庫全庫備份與直接還原一致性 (Direct Database Restore)**：
   - 頂部導航列 (TopSubWindow) 與基本資料 (BasicSettingsHubWorkspace) 雙入口 100% 統一。
   - 支援 `.sqlite` / `.db` 二進位實體檔案與 `.sql` 純文字指令檔一鍵拖曳／選取上傳。
   - 系統自動解析檔案類型與大小，提示安全覆蓋預警，提供「還原前先下載當前庫備份防呆 (建議)」按鈕。
   - 1 秒內以 WebAssembly 掛載覆寫，完成後**自動調用 `reseedDocumentSequences()` 全自動校準 12 大模組單據流水號指針**，防止撞號與主鍵衝突。

## 🏗️ 案場建造物二階字典、預算協力廠商發包與防裁切懸浮選單

1. **建造物類型自訂兩階層字典 (`BUILDING_CATEGORY_TREE`)**：
   - 解決硬編碼類型無法適應不同營造行業與工種之限制。
   - 採「大項 ➔ 小項」結構，表單嚴格約束僅能選取第二階小項，大項僅供分類群組展示。
   - 提供專屬 `BuildingCategoryManagerModal` 支援自主維護大類與細項。
2. **預計協力廠商發包預算主表 (`project_budget_partners`)**：
   - 支援案場新增時預估各工料協力廠商與預估發包金額。
   - 建立 `idx_budget_partners_project` 複合索引提升彙整效能。
3. **二階協力廠商公司名稱字典 (`SUBCONTRACTOR_CATEGORY_TREE`)**：
   - 核心原則：**清單只需公司名稱，不用冗長細部資料**（避免干擾）。
   - 第一階工料分類（鋼材、混凝土、拆圖、屋頂浪板等），第二階為該分類下之公司名稱清單。
4. **懸浮式選單防裁切架構 (Floating Portal Architecture)**：
   - 徹底杜絕響應式表格 `overflow-x-auto` 或彈窗 `overflow-y-auto` 裁切遮蔽下拉選單的問題。
   - 使用 `ReactDOM.createPortal(..., document.body)` 搭配 `fixed` 絕對座標定位與 `z-[99999]`。
5. **進貨與計價唯讀對帳與待請款差額檢警機制**：
   - 只由進貨端與計價端調取資料彙整，嚴禁修改。
   - 自動核算 $\text{待請款差額} = \text{累計已進貨} - \text{累計已請款}$，差額 > 0 時標註顯眼「待請款」警示，杜絕協力廠商忘記請款之漏洞。
   - 點擊廠商時提供獨立隔離穿透對帳視窗 (`ProjectVendorInboundModal`)，嚴密過濾單一案場單一廠商之進貨單據明細。
