# 客製化營造工程 ERP 系統架構規劃方案 (Enterprise Engineering ERP)

本規劃方案依據《ERP全模組資料庫欄位與用途總表.MD》之單一真實來源 (SSoT) 與《系統憲法》全套架構規約，為企業打造具備「互動式業務流程地圖」、「全域資安防呆防弊」、「SQLite 本地便利備份與 SQL 匯出」以及「10 大核心業務全鏈貫通」的現代化客製化 ERP 系統。

## 使用者確認事項與關鍵決策 (User Review & Critical Decisions)

> [!IMPORTANT]
> 根據前期討論與偏好選擇，系統已鎖定以下核心架構方針：

- **已確認決策 1（資料庫與備份）**：採用 **SQLite 本地關聯式資料庫** 作為核心引擎，並內建「**一鍵 SQL 匯出 (SQL Dump)**」、「**二進位資料庫下載備份 (.sqlite)**」與「**SQL 指令稿匯入還原**」功能。既滿足企業對檔案式極速備份、免安裝外部資料庫伺服器的便攜需求，又符合高標準關聯式 SQL 查詢與事務 (ACID) 完整性。
- **已確認決策 2（首頁視覺與互動）**：首頁主儀表板落實「**互動式業務生命週期地圖 (Interactive Business Lifecycle Map)**」佈局。涵蓋「案場立項 → 商業夥伴 → 報價 CPQ → 現場進貨驗收 → 估驗計價 → 財務應收付/票據 → 營運戰情大腦」，節點具備即時待辦數量標記，點擊直接開啟對應模組或單據作業。此外，軟體名稱、Logo、副標題全面使用動態變數，由 Superadmin 於「系統中樞 ➔ 軟體程式設定」中自訂，杜絕任何第三方商標侵權風險。
- **已確認決策 3（單一事實來源 SSoT）**：全系統資料表規格以 `ERP全模組資料庫欄位與用途總表.MD` 為最高準則，嚴格落實憲法防弊三件套：
  1. **全域零負數鐵律**：折讓、扣款、減項均以正數保存並由公式減除；前端介面在減項模式自動觸發「**粉紅扣款防呆視覺 (Pink Deduction UI)**」。
  2. **過帳實體快照 (Frozen Snapshot)**：單據一旦過帳，客戶名稱、廠商統編、專案名稱與稅率即刻凍結，禁止歷史篡改。
  3. **軟刪除 (isDeleted) 與樂觀鎖 (version)**：所有業務表單預設支援並行防覆寫與操作審計歷程 (AuditLog)。
- **已確認決策 4（商業夥伴模組實務架構）**：
  1. **雙頁籤切換**：頂部明確提供 `[業主名冊 (Clients)]` 與 `[合作廠商 (Vendors)]` 雙頁籤切換，不另開無意義的獨立頁面。
  2. **一鍵自廠商引薦/加入變業主**：業主名冊支援搜尋既有合作廠商並一鍵引薦轉換為業主，自動帶入基本資料，維持 SSoT 單一真實來源。
  3. **多層級服務工項下拉**：廠商服務項目採用階層式下拉式選單（如：結構工程 ➔ 模板/鋼筋；裝修工程 ➔ 泥作/油漆），介面簡潔乾淨不堆疊標籤。
  4. **多地址、多電話、多聯絡人**：支援公司登記地、工廠、工務所等多筆地址（預設為通訊地址），以及多組電話與窗口聯絡人。
  5. **金融帳戶與支票記錄**：內建台灣銀行代碼下拉選單；支援收發支票完整帳務資訊（銀行、帳號、票號、開票日、到期日等）留存。
  6. **手續費公司吸收**：工程請款預設不內扣匯費與郵費，由公司自行吸收（`bankFeePayer = COMPANY`）。
  7. **憑證影像留存與標準附件對接**：存摺封面與支票影本/PDF 上傳留存，標準對接 Phase 9 附件架構。
- **已確認決策 5（基建先行與模組分工接棒順序）**：
  1. 當前全力完成 Phase 3 商業夥伴模組。
  2. 商業夥伴模組完成後，下一棒立即由接手夥伴優先開發 Phase 9 通用附件與無紙化歸檔模組，封裝全系統共用上傳與預覽元件（支援 WebP 壓縮與 PDF 燈箱預覽）。
  3. 後續報價銷售 (Phase 4)、採購發包 (Phase 5)、估驗計價 (Phase 6) 直接隨插即用該附件元件，杜絕重複造輪子。
- **已確認決策 6（角色職責與介面架構大整併：Superadmin 軟體程式設定 vs Admin 營運法規中樞）**：
  1. **Superadmin 專屬：軟體程式設定 (APP_CONFIG)**：
     - 獨立專屬選單，僅最高管理員（`isSuperadmin`）登入時可見，Admin 與一般同仁連看都看不到。
     - 專門設定「這套軟體程式本體」，與客戶公司之日常業務、財務法規徹底解耦。
     - 涵蓋範圍：軟體品牌名稱（如頂欄「田頭」）、副標題（「A1 商務應用雲」）、版本號（「v2.5.0-PRO」）、HTML分頁標題、頁腳版權宣告、全模組開放授權開關 (`APP_ENABLED_MODULES` Feature Flags)、全域緊急公告廣播條、維護模式等。
  2. **Admin 專屬：基本資料營運法規中樞 (SETTINGS)**：
     - 原獨立之【公司設定 (COMPANY)】正式整併合併進入【基本資料 (SETTINGS)】，大幅精簡左側導航選單。
     - 介面採五大階層分頁（Tabs）：
       - Tab 1: `[營運法人實體]`：集團母體、各子公司統編、地址、負責人、重要人物、銀行帳戶等組織主檔。
       - Tab 2: `[法定稅制與健保]`：法定營業稅率 (%)、二代健保補充保費率 (%)、法定最低基本工資 (元，如現行 28,590 元 / 時薪 190 元)、發票尾差容差 (元)、印花稅，以及**法規未來預約生效排程機制 (Scheduled Effective Timestamps，到期自動無痛切換，免熬夜修改)**。
       - Tab 3: `[工程合約與預算內控]`：預設估驗保留款扣留率 (%)、超支預算防呆模式 (STRICT / WARN)、**預設請款票期開關（支援天數或一鍵關閉為無票期 · 即期付款）**、保固期月數。
       - Tab 4: `[單據跳號規則]`：各業務單據前綴與流水號計數器維護，落實**「嚴格禁止往前回溯重號、允許往後跳號、產號防碰撞自癒」**三大內控憲法。
       - Tab 5: `[資料庫安全與歸檔備份]`：**實體化內嵌面板（嚴禁空按鈕）**，展示全模組即時健康度、2010～2026 歷年唯讀封存快照實體清冊、時段過濾（全部/年度/區間）模組化備份還原面板。
     - **動態法規解耦**：所有計算公式一律動態讀取資料庫，法規修改時 Admin 直接線上調整或預約排程即時生效，徹底免除 Superadmin 介入與改寫程式碼成本。
- **已確認決策 7（進貨管理模組與會計對帳大水池之職責分離專責架構）**：
  1. **定位與名稱**：定名為「**進貨管理 (Inbound Goods Management)**」，首波優先精雕現場進貨簽收與料件單價管理，未來視營運擴張再擴充採購詢比議價單 (PO)。
  2. **直接認列案場成本 (A 模式)**：材料貨物直接送抵特定工區案場，進貨即直接歸戶該專案成本，免去中心倉庫存與調撥之繁複手續，最貼合營造現場實務。
  3. **進貨模組專責邊界 (Strict Boundaries & Separation of Concerns)**：
     - **專責處理**：進貨日期、合作廠商 (VENDOR)、歸屬案場 (PROJECT)、廠商送貨單號 / 現場簽收單號、簽收憑證（支援拍照/上傳附件存證）、物料明細（品名規格、計量單位、數量、約定單價、小計金額）。
     - **嚴格不碰**：❌ 不打發票號碼 ❌ 不做折讓扣減 ❌ 不排定付款日期 ❌ 不碰放款沖銷與支票開立。
  4. **會計對帳「廠商往來大水池 (Vendor Ledger Pool)」接軌機制**：
     - 進貨單以 `PENDING_BILLING`（待對帳）狀態進入該廠商的帳款大水池。
     - 每逢月底月初收到廠商請款對帳單時，會計拉出該廠商水池中所有待對帳進貨簽收單逐筆核對。
     - 若無疑問即勾選對帳；若當期無發票或有疑義，單據放著不勾選，自動沉澱在水池中順延至下期對帳。
     - 會計於對帳階段才補登發票號碼（或註記免用/跨期延後補票）、計算營業稅 (5%)、填寫折讓扣減（如領現金折讓、零頭折讓），產出應付淨額。
     - 排定「預計付款日」，系統提供「**廠商應付水位總表 / 欠款提醒看板**」，即時警示全公司尚欠各廠商多少水（未結款項）及預計何時放款。
  5. **PBAC 雙重確認權限設計 (Dual-Confirmation & Separation of Duties)**：
     - 打單、對帳、付款三權在權限底層明確分立。
     - 現行二人架構：人員 A 具備「打單 + 對帳」，人員 B 具備「對帳 + 付款」，形成業務與金流的雙重確認交叉防弊；未來團隊擴編時，可於後台一鍵拆分為 A (打單)、B (對帳)、C (付款) 三人完全分立。
  6. **資料對接錨點 (Data Hooks)**：
      - 每筆進貨單提供全域唯一識別單號（`INB-YYYYMM-XXXX`）、明細唯一鍵值、`billingStatus: 'PENDING_BILLING' | 'BILLED'`，並預留 `reconciliationId` 供會計對帳單過帳時回填勾稽。
- **已確認決策 8（五大維護功能整併為底層系統管理中樞 System Hub）**：
  1. **問題痛點**：原先「基本資料」、「帳號管理」、「程式設定」、「小程式庫」、「藍圖總綱」分散在左側功能列，導致選單項目多達 16 個，管理項與業務項混雜，大幅稀釋日常工程操作效率。
  2. **解決方案**：將上述 5 項全面整併為底部單一功能頁面【系統設定與管理中樞 (System Hub / SETTINGS)】，透過頂部 Tabs 進行分頁切換：
     - `[營運基本資料 (BASIC)]`：法人設定、法定稅制、合約慣例、單據跳號、資料庫備份 *(Admin / Superadmin)*
     - `[帳號與權限 (USERS)]`：三層身分矩陣、PBAC 授權、審批額度、安全稽核 *(Superadmin 或特許 Admin)*
     - `[軟體程式設定 (APP_SETTINGS)]`：軟體抬頭品牌、版本號、全域公告廣播、Feature Flags *(Superadmin 專屬)*
     - `[常用小程式庫 (MINI_APPS)]`：台灣 3+3 郵遞區號選取器、全國 414 家金融機構速查 *(共用工具庫)*
     - `[藍圖總綱與規約 (ROADMAP)]`：憲法規約手冊、系統架構討論綱要 *(Superadmin 專屬)*
  3. **身分權限過濾**：依據登入角色權限自動過濾 Tab，非授權分頁完全不予渲染；一般同仁 (USER) 無系統設定權限者連左側底層按鈕都不會顯示。
- **已確認決策 9（全新左側選單 9+1 順序排列哲學與業務流程去裝飾化實戰原則）**：
  1. **9 大常用業務模組由上至下依營造生命週期排列**：
     `營運儀表 ➔ 案場工程 ➔ 廠商工班 ➔ 報價預算 ➔ 進貨管理 ➔ 估驗請款 ➔ 財務收支 ➔ 保險箱 ➔ 戰情指揮`
  2. **採購發包暫時隱藏**：目前聚焦進貨管理現場簽收（A 模式），未來若需招標採購詢價再以獨立模組無縫掛載。
  3. **業務流程去裝飾化，回歸純粹實戰**：
     - **徹底移除頂欄「業務流程」按鈕與彈窗**：經深入檢視，舊有流程圖標題不連動、動線無實質功能、節點非真實作業、底層權限按鈕重複無效，且僅限 Admin 可看（Admin 懂系統不需看，一般同仁需培訓卻看不到），存在根本矛盾，故徹底卸除。
     - **營運儀表板置頂業務生命週期卡片 (`BusinessLifecycleMapCard`)**：移除繁複的展開流程圖接口，僅保留極致俐落的 1~7 節點快速穿透捷徑（案場 ➔ 廠商 ➔ 報價 ➔ 進貨 ➔ 估驗 ➔ 財務 ➔ 戰情）。
     - **教育訓練獨立模組化儲備**：未來若有新進同仁培訓需求，再另闢專屬獨立的「教育訓練模組 (Training Module)」提供各崗位真實 SOP 指南。

## 1. 系統概覽與核心理念 (Overview & Core Concept)

- **系統定位**：專為台灣營建工程、室內裝修、機電工程與專案型服務企業量身打造的全功能 ERP 系統。
- **目標角色 (Personas)**：
  - **經營者 / 董事長 / 總經理**：直擊「營運戰情室」，即時監控專案毛利雷達、真實可用現金水位（扣除未兌現支票與預估稅費）及待補簽追加減工程風險。
  - **專案經理 (PM) / 工務主管**：專案案場立項、WBS 工作拆解、現場施工進度回報、發包估驗初審、雙軌表單防呆暫存。
  - **採購發包專員**：供應商議價、採購單開立、預付款扣抵沖銷、防止超額發包。
  - **財務會計 / 出納**：應收應付對帳、發票拆單小精靈（多發票拆單對應不同法人）、應收付票據到期託收與兌現沖銷、三柱/四柱平衡檢核。
- **核心價值**：
  解決傳統 ERP 死板、難以因應工程界「現場先做後補單」、「業主合約追加減延遲」、「多子公司稅務掛帳」、「支票票期長且調度繁複」之業界實務痛點，在嚴格的內控防弊與極致的操作彈性之間取得最佳平衡。

### A. 關鍵操作流程 (Key User Flows)

1. **流程地圖作業流 (Flowchart-Driven Workflow)**：
   使用者進入系統首頁即見清晰的「互動式業務流程圖」，節點醒目標示當前狀態（如 `採購單 (3筆待核)`、`下包估驗 (2筆待計價)`），點擊即直接穿透至對應模組或單據作業。
2. **專案與預算拆解流程 (Project & WBS Flow)**：
   PM 建立專案案場，設定預算上限與工項節點。支援「草稿暫存 (Draft Fallback)」與「正式過帳鎖定 (Project Lock)」，防止預算未核先發包。
3. **CPQ 報價與銷售修訂流 (Sales & Revision Flow)**：
   業務開立報價單，支援多版次 (REV-A, REV-B) 平行比對，設定請款里程碑比例 (如 30%-40%-30%)。輸入負數扣款項目時，介面自動亮起柔和粉紅警示色，強制輸入正數並由引擎扣除。
4. **進貨簽收與直入案場作業流 (Inbound Goods & Site Cost Flow)**：
   工區或打單同仁收到送貨簽收單，登錄進貨單並直接歸戶至特定工區案場認列材料成本（A 模式）。登載項目、數量、約定單價與廠商送貨單號，並支援附件/紙本拍照上傳存證。單據過帳後狀態為 `待對帳 (PENDING_BILLING)`，自動注入該廠商之帳款大水池。
5. **發包與瀑布式估驗結算流 (Procurement & Valuation Flow)**：
   工務依合約計價，系統自動帶出前期累計完成度、本期估驗金額、預付款自動扣抵 (Prepaid Deduction) 與保留款 (Retention Rate, 如 10%)。
6. **廠商大水池對帳、發票補登與到期放款沖銷流 (Vendor Ledger Pool Reconciliation & Cash Flow)**：
   會計於月底或月初收到廠商請款單時，拉出該廠商水池中所有待對帳進貨單勾選對帳；跨期或無發票者留置水池下期續對。在此環節補登發票號碼、計算營業稅 (5%)、扣抵折讓（如領現金折讓），排定「預計付款日」並於儀表板提供「廠商欠款水位與到期預警」。放款時開立支票或匯款，自動檢驗「票據號碼防重」、「三柱借貸平衡」與兌現沖銷。
7. **資料庫一鍵備份與匯出中心 (Database Management Center)**：
   專屬資料管理介面，提供「即時產生 SQLite 副本下載」、「匯出完整 SQL 建表與資料 INSERT 語法 (.sql)」、「上傳 SQL 還原」與「重置測試範例資料」。

## 3. 核心技術決策與權衡 (Key Product Decisions & Trade-Offs)

### 決策 1：本地 SQLite 搭配全自動備份與 SQL 匯出引擎
- **採納方案**：使用基於 Node.js / TypeScript 運行之關聯式 SQLite，配備自動維護的 SQL 序列化產生器 (SQL Dump Engine)。
- **原因與效益**：
  1. **免維護外部伺服器**：無須繁瑣的雲端連線字串或外部資料庫安裝，一鍵啟動立即運行。
  2. **備份極度方便**：使用者可隨時一鍵下載完整的 `.sqlite` 資料庫二進位檔，或一鍵產出通用的標準 `.sql` 純文字檔案，隨身攜帶、隨時備份到隨身碟或雲端硬碟。
  3. **百分百 SQL 兼容性**：未來若企業擴大規模需要遷移至 PostgreSQL 或 MySQL，只需匯出 SQL 即可無痛轉移。
- **捨棄方案**：
  - 捨棄純前端 localStorage（無法支撐複雜的多對多關聯、事務性與大量明細）。
  - 捨棄重量級外置 DB 依賴（避免環境網路或憑證失效造成系統中斷）。

### 決策 2：互動式業務生命週期流程地圖與單據穿透
- **採納方案**：在首頁設計高響應的生命週期流程圖，清晰描繪「案場 → 夥伴 → 報價 → 現場進貨驗收 → 估驗 → 應收付/票據 → 戰情」主幹線，節點動態綁定資料庫統計數據。
- **原因與效益**：工程業界單據關係複雜，流程地圖能給予新手與管理者最直觀的整體全景視野，大幅降低教育訓練成本。

### 決策 3：嚴格落實《ERP全模組資料庫欄位與用途總表》12 模組欄位
- **採納方案**：嚴格依據總表定義之模型純量欄位建構資料結構（包含 `poNumber`、`counterpartyNameSnapshot`、`postedTaxRate`、`retentionDeductionAmount`、`isPrepaidDeduction` 等快照與計算欄位）。
- **原因與效益**：確保資料庫層級具備法律證據級別的防篡改能力，滿足會計師查帳與工程業保固款追蹤的嚴格要求。

### C. 資料庫備份、年度封存與還原機制 (Backup, Archiving & Restore Strategy)

#### 1. 全庫鏡像備份與還原 (Ghost 模式與全域介面統一)
- **頂部與基本資料雙入口完全統一**：頂部 Header 下拉選單與「基本資料 ➔ 資料庫安全與歸檔備份」分頁採用完全一致的功能項目、命名、圖示與防呆流程。
- **一鍵二進位備份 (.sqlite)**：後端即時封裝完整 SQLite 資料庫檔案，供系統管理員離線保存或版本快照。
- **一鍵全庫 SQL 語法匯出 (.sql)**：自動輪詢全系統資料表，產出完整的 `CREATE TABLE` 與 `INSERT INTO ...` 之標準 SQL 文本。
- **全庫檔案一鍵上傳直接還原 (Direct File Restore)**：
  - 支援使用者直接選取或拖曳上傳 `.sqlite`、`.db` 實體二進位庫或 `.sql` 指令檔。
  - 系統自動解析檔案類型與大小，提示安全覆蓋預警，並提供一鍵「還原前先下載當前庫備份防呆」功能。
  - 1 秒內以 WebAssembly 記憶體實體重新掛載並覆寫本地持久層，無需重啟伺服器。
  - 還原後系統**自動調用 `reseedDocumentSequences()` 全自動校準 12 大模組單據流水號指針**，防止撞號與主鍵衝突。

#### 2. 年度唯讀封存快照 (Annual Archival Snapshots)
- **運作機制**：平時主庫保留所有歷年業務資料，不切斷在建工程與保固中合約。每年底結算後，系統自動或一鍵封裝獨立的年度唯讀 SQLite 檔案（如 `ERP_ARCHIVE_2025.sqlite`，內部標記 `isSealed = 1`）。
- **三大落地情境**：
  1. **免啟動主庫之靜態離線查閱**：使用者可在「資料庫查詢中心」直接以唯讀模式掛載任一年度封存檔，進行歷史單據調閱，極度省記憶體且不干擾正式線上營運庫。
  2. **新電腦系統遷移選擇性載入**：新機安裝全新系統時，使用者可勾選載入「近 5 年或 10 年」之封存包，過於久遠的歷史檔案留在外接硬碟，新庫保持極致輕快。
  3. **災難救援安全底線**：各年度歷史封存檔不可竄改，可作為資料庫重創時的乾淨歷史基底。

#### 3. 模組化選擇性備份與時段篩選還原 (Modular & Time-Filtered Backup / Restore)
- **模組清單勾選與時段範圍過濾 (Time-Filter)**：
  - 使用者可選擇備份「全部」或「指定某幾個核心模組」（如：只匯出 `[公司與集團架構]`、`[專案案場與WBS]`、`[商業夥伴廠商檔]`、`[採購發包與單據]`、`[財務發票與支票]` 等）。
  - **時段範圍彈性過濾**：支援「全部歷史 (`ALL`)」、「指定單一年度 (`YEAR`)」或「自訂起訖日期區間 (`RANGE`)」，經跨 2010～2026 年（17 年歷史資料）實機驗證，精準篩選特定年度或區間之單據，並連帶打包相依主檔。
  - 匯出為標準模組化 JSON Package，包含該模組所屬的資料表資料、結構版本號與建立時間戳記。
- **模組相依性智慧檢核 (Dependency Validation)**：
  - 當匯入下游模組（例如：估驗計價或採購單）時，系統自動掃描關聯之上游主檔（專案 ID、廠商 ID、公司 ID）。
  - 若發現缺漏關聯，主動列出警示清單，引導測試人員補齊或連帶勾選還原。
- **雙軌還原策略 (Restore Strategy Options)**：
  - **模式 A：覆蓋替換 (UPDATE)**：清空或覆蓋更新目標模組同 ID 之最新版本，其餘未勾選模組保持不變。
  - **模式 B：略過既有 (SKIP)**：以主鍵與業務唯一單號比對，若主庫已存在則略過不重複插入，筆數不膨脹。
  - **還原後自動自癒校準流水號**：還原寫入完成後自動重置 `document_sequences`，防止重號。

#### 4. 附件檔案實體與資料庫徹底分離架構 (Relative Path & Vault)
- **資料庫零 BLOB 鐵律**：資料庫僅保存中繼資料、SHA-256 雜湊碼與**本機相對存放路徑 (`storagePath`)**，資料庫本體永遠維持數十 MB 輕量。
- **相對目錄結構分流**：
  - `storage/public_docs/`：非敏感文件（現場施工照片、工務日報、CAD 圖說）。
  - `storage/secure_vault/`：機敏文件（底價標單、合約原件、薪資明細），採 **AES-256-GCM 對稱加密** 儲存為 `.enc` 檔案，讀取時串流解密。
- **隨身攜帶與搬遷**：移機時整包專案複製，相對路徑 100% 保持有效不斷鏈。

#### 5. 毫秒時間戳記與三柱版本冪等還原狀態機 (Idempotent Restore State Machine)
- **實體唯一識別**：每筆資料以全域唯一 `id`（UUID 或毫秒業務流水碼）為身分標識。同一毫秒多筆同額支出（如兩筆 5,000 元）因 `id` 不同而被視為獨立合法交易，絕不誤刪或重複合併。
- **版本比對狀態機**：
  - `id` 不存在 ➔ `INSERT` 全新寫入。
  - `id` 已存在且備份檔 `version == 主庫 version` ➔ `SKIP` 跳過不重複寫入。
  - `id` 已存在且備份檔 `version > 主庫 version` ➔ `UPDATE` 覆蓋更新（修正版生效）。
  - `id` 已存在且備份檔 `version < 主庫 version` ➔ `IGNORE` 略過（主庫資料更新）。

#### 6. 四大漏洞排查與工程防禦鐵律 (Hardened Safeguards)
- **外鍵拓撲排序與外鍵事務保護**：還原時依相依樹階層依序寫入；事務期間關閉約束，提交前強制執行 `PRAGMA foreign_key_check`。
- **單據跳號計數器自癒校準與防回溯鐵律 (Sequence Reseed & Anti-Rollback Rule)**：
  - **禁止往前回溯**：嚴格禁止手動或介面將流水號計數器修改為小於等於資料庫現存最大單號的值。允許往後跳號（如因作廢跳號），但絕對杜絕回溯產生重複單號。
  - **產號防碰撞自癒**：產號引擎 (`getNextDocumentNumber`) 在發放單號時，自動比對該業務表；若發現該號碼已被使用，自動以原子操作躍升至 `現存最大序號 + 1`，雙重保險確保 100% 唯一性。
  - **災難還原指針強制對齊 (`reseedDocumentSequences`)**：從 SQL Dump、SQLite Binary 或年度快照還原舊庫後，系統提供一鍵全庫單據指針重置工具，自動遍歷所有實體單據表重新校準指針，確保還原後新增單據 100% 不撞號。
  - **開發注意事項 (Developer Discipline)**：前端與後端開立新單時，**一律調用 `getNextDocumentNumber(moduleKey, docDate)`**，嚴禁在元件程式碼中寫死 `-001` 或手動拼接字串。前綴變更一律經由 `validateDocumentPrefixConflict` 校驗，禁止跨模組重疊前綴。
- **年度封存自包含快照 (Self-Contained Snapshot)**：封存單據連帶封存關聯專案與廠商主檔摘要，單獨開啟歷史庫絕不斷鏈。
- **POSIX 正斜線相對路徑標準化**：附件路徑統一採 `/` 格式，杜絕 Windows 反斜線跨環境相容性問題。

## 5. 實施階段與驗證指標 (Implementation Roadmap)

1. **第一階段：系統基礎設施、資料庫與流程導航總覽（已就緒）**
   - 建立全套 SQLite 資料表 Schema（以總表為單一準則）
   - 完成備份中心（SQLite 檔案下載、SQL 匯出/匯入、範例種子資料載入）
   - 完成頂部導航與全生命週期的「互動式業務流程地圖」
2. **第二階段：Phase 3 商業夥伴模組（當前衝刺重點）**
   - 實作「業主名冊」與「合作廠商」頂部雙頁籤切換
   - 實作「搜尋既有合作廠商並一鍵引薦轉換為業主」防呆機制
   - 實作廠商服務項目「多層級下拉式選單」
   - 實作多地址（預設通訊地址）、多電話、多窗口聯絡人動態管理
   - 實作金融機構代碼下拉選單（含總行與分行代碼）、銀行帳號與收發支票完整記錄
   - 實作手續費預設由公司吸收 (`bankFeePayer = COMPANY`)
   - 實作存摺封面照片與收發支票影本/PDF 上傳預覽與標準附件中介資料庫接口
3. **第三階段：Phase 9 通用附件與無紙化歸檔（接手夥伴最高優先）**
   - 接手夥伴打造全系統共用 `<AttachmentUploader />` 與預覽燈箱元件
   - 封裝圖片自動 WebP 壓縮與 PDF 線上即時預覽功能
   - 建立全域保險箱 (Universal Vault) 與實體相對路徑管理，隨插即用提供後續各模組調用
4. **第四階段：專案案場、報價與採購發包估驗計價（調用共用附件）**
   - Phase 2 專案案場與 WBS 工項節點建檔
   - Phase 4 報價單多版次修訂與粉紅扣款折讓防呆介面（直接掛載報價單 PDF 附件）
   - Phase 5 採購單開立與過帳實體文字快照（直接掛載供應商報價單與比價表）
   - Phase 6 下包承攬合約與估驗計價單（瀑布式計算累計完成度、保留款與預付扣抵，直接掛載計價發票收據憑證）
5. **第五階段：財務應收付、支票管理與營運戰情室大腦**
   - 實作應付憑單、發票拆單小精靈
   - 實作應收付支票託收、兌現與三柱平衡檢核
   - 實作營運戰情室（即時可用資金水位、專案毛利雷達、Pending CO 風險指標）
6. **第六階段：編譯驗證、全鏈壓力測試與交付審查**
   - 執行 `compile_applet` 確保前後端 TypeScript 零報錯
   - 驗證各單據跳轉、過帳防篡改與資料庫備份還原完整性
